# Alexa skill — setup

Voice control for ohMyBuying. The skill talks to a Vercel serverless endpoint at `/api/alexa`, which talks to Supabase. Account linking is link-by-code (the Alexa app types a 6-character code generated by your ohMyBuying app).

## What's in this folder

- `skill.json` — the skill manifest (publishing info, endpoint, locales). Replace `YOUR-DEPLOYMENT.vercel.app` with your real deployment hostname before submitting.
- `interaction-models/en-US.json`, `interaction-models/es-ES.json` — voice models. Edit sample utterances and the `ListName` slot values to match your users' habits.

## Prerequisites

- An [Amazon Developer](https://developer.amazon.com/alexa/console/ask) account.
- The ohMyBuying app deployed to Vercel with the env vars below.

## Vercel env vars

Set these in **Project → Settings → Environment Variables** (Production scope):

| Name                          | Value                                                  |
| ----------------------------- | ------------------------------------------------------ |
| `SUPABASE_URL`                | Your Supabase project URL (or `http://localhost:8000`) |
| `SUPABASE_SERVICE_ROLE_KEY`   | The service-role key (from Supabase → Project Settings → API) |

⚠️ **Never** expose `SUPABASE_SERVICE_ROLE_KEY` to the browser. It is only read by `/api/alexa.ts`, which Vercel runs server-side.

## Deploy the skill

You can do this via the Alexa Developer Console UI **or** the ASK CLI. UI is faster for the first time.

### Option A — Alexa Developer Console UI

1. Go to https://developer.amazon.com/alexa/console/ask → **Create Skill**.
2. **Skill name:** `ohMyBuying`. **Primary locale:** `English (US)`. **Choose a model:** `Custom`. **Choose a method to host your skill's backend resources:** `Provision your own`.
3. Once created, in **Build → JSON Editor**, paste the contents of `interaction-models/en-US.json`. Save and Build Model.
4. **Build → Invocation Name:** `oh my buying` (already set in the JSON).
5. **Build → Endpoint:** `HTTPS`, paste `https://YOUR-DEPLOYMENT.vercel.app/api/alexa`. SSL Certificate Type: `My development endpoint is a sub-domain of a domain that has a wildcard certificate from a certificate authority`.
6. Add the **es-ES** locale: **Language → Add → Spanish (ES)**, then paste `interaction-models/es-ES.json` into its JSON Editor and Build.
7. **Test** tab → enable testing in `Development`. Try: `"open oh my buying"`.

### Option B — ASK CLI

```bash
npm i -g ask-cli
ask configure
ask new --template "" --skill-name ohMyBuying
# overwrite the generated files with the ones in this folder, then:
ask deploy
```

## Linking the user account

1. In ohMyBuying, sign in → click **Alexa** in the header → **Generate code**.
2. In the Alexa app (or the developer console Test tab), enable the skill.
3. Say: *"Alexa, ask oh my buying to link with code XXXXXX"* using the 6 characters.
4. After "Your account is now linked" you can use any of the supported phrases.

## Supported phrases

**English:**
- "Alexa, ask oh my buying to add eggs to my groceries list."
- "Alexa, ask oh my buying to remove milk from my groceries list."
- "Alexa, ask oh my buying what is on my groceries list."

**Español:**
- "Alexa, pídele a oh my buying que añada huevos a mi lista de compras."
- "Alexa, pídele a oh my buying que quite leche de mi lista de compras."
- "Alexa, pregúntale a oh my buying qué hay en mi lista de compras."

## Troubleshooting

- **"Generate code" fails with a 404 / `PostgREST error=42883` (`function gen_random_bytes(integer) does not exist`)** — the hosted Supabase project is missing the `pgcrypto` extension that `issue_alexa_link_code()` uses to mint codes. Run `create extension if not exists pgcrypto with schema extensions;` in the SQL editor (it's now included at the top of `supabase/schema.sql`). The function calls `extensions.gen_random_bytes(...)` schema-qualified, because it runs with `search_path = public` and pgcrypto lives in the `extensions` schema. Note the DB error surfaces as a bare `42883` — inspect the full JSON response body (browser Network tab) to see the real `function ... does not exist` message.
- **"Your account is not linked yet"** — generate a fresh code in the app and try again. Codes expire in 10 minutes and are single-use.
- **"I couldn't find a list called X"** — the spoken name is matched case-insensitively, with diacritics stripped, and supports prefix/contains. If your list is named with a long phrase, add the spoken form to the `ListName` slot's `values` array in the interaction model and rebuild.
- **Endpoint validation fails** — Amazon requires HTTPS with a valid cert and a verified `signature` header on every request. The Vercel handler verifies the signature; check the function logs.
- **Skill submission rejected** — Amazon's certification requires terms-of-use and privacy-policy URLs. Update the placeholders in `skill.json` to point at your actual policy pages.

## What's deliberately out of scope here

- **Real OAuth account linking** — we used a code-link flow because it's simpler. If you ever want "Sign in with ohMyBuying" inside the Alexa app, you'll need to add an OAuth 2.0 authorize/token pair on Vercel.
- **Push reminders to Alexa** — the in-app reminder banner doesn't push to Alexa. To do that, add an Alexa Reminders API call in a server-side cron job that fires when `due_reminders()` returns rows.
